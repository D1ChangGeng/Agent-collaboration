# P2 cross-machine Runtime execution boundaries

- Remote senders consume committed Endpoint, Connection and authority-key data
  plus a sender-owned signing credential. Receiver-local certificate, Node key,
  ledger and process paths stay on the receiving Machine.
- A receiver can bind a private local listener separately from its registered
  locator. A `tunnel` route counts only when it preserves the end-to-end TLS
  stream, certificate fingerprint and signed delivery protocol. SSH remains
  deployment/control transport and is not Runtime delivery evidence.
- Windows Receiver capacity uses ACL-private non-reparse storage,
  `WindowsJobSupervisor`, and a schema generated by the exact Codex binary.
  Built-in `:workspace` is a `default_permissions` value, not an entry inside a
  custom filesystem table. The Driver reads back active permissions, approval
  policy, cwd and disabled multi-agent features.
- Linux Receiver capacity uses owner `0700/0600` paths,
  `SystemdUserSupervisor`, the reviewed bwrap helper and a digest-pinned Codex
  distribution. Both platforms terminate owned process trees on construction
  failure and Receiver shutdown.
- Runtime execution evidence retains the commit/tree, Machine/Harness bindings,
  receipts and readbacks of the run that produced it. A later source HEAD does
  not rewrite that historical result. Classify a source delta by the mechanisms
  it affects; documentation and license changes do not imply changed Runtime
  behavior. State separately which later-candidate claims are historical,
  directly observed, or independently reviewed.
