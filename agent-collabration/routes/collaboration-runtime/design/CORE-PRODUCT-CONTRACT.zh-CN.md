# ACS Core 产品契约

状态：供架构整改与实现拆分使用的设计草案。

源码核对基线：`e208a44f49927ead846623916ada828277401d00`。
本文描述目标行为；当前实现的差异在迁移清单中列出。

用户已确认业务价值与实际能力。本轮授权、人工到期与 Harness 限制的具体
清理范围见 [清理范围与业务影响](AUTHORIZATION-EXPIRY-CLEANUP.zh-CN.md)。
该清理保持现有业务关系，运行实现的完成状态单独验收。

## 产品目标

ACS 帮助用户通过本机或网页 Agent，在已连接的机器和项目中组织协作、
派发任务、获取结果，并在断线、重启和会话替换后继续工作。

默认使用场景为同一安装者控制的机器、项目和多个 Harness。
安装者在首次连接时选择机器、项目访问位置及 Harness；配置持续保存。
后续操作沿用这些选择，运行服务自动处理连接恢复和执行入口创建。

外部 Agent 负责目标、任务拆分、职责选择、委派、评审判断和接受决定。
Core 负责可重复执行的协作命令、持久记录、投递与执行连续性。

## 用户能够完成的闭环

1. 把已有机器连接到 ACS，并选择要使用的 Harness。
2. 在项目中创建 Management Root、Route 和协作成员。
3. 交给指定机器或成员一项任务。
4. ACS 自动连接目标并接入或创建符合请求的执行会话。
5. Agent 执行任务，用户能够查看进度、发消息和等待结果。
6. 执行结果进入原任务和 Inbox，可跨客户端读取。
7. 用户或外部 Agent 决定下一项工作、Review、接受或取消。

例如：用户请求在指定机器的指定项目运行测试。ACS 使用已有连接配置，
检查真实连接、准备对应会话并提交请求。缺少历史会话时可以创建新会话。
目标暂时离线时，任务保持可恢复状态，并返回具体原因和重试状态。

## Core 的职责

| 能力 | Core 提供的保证 |
|---|---|
| 项目和协作组织 | 保存项目、Root、Route、成员职责及当前关联工作 |
| 机器连接 | 保存安装者确认的连接配置，自动建立和恢复连接 |
| 消息 | 返回持久收件凭据，跟踪投递和响应，重试保留请求身份 |
| 执行 | 调用具体 Harness 适配器，保存会话与执行关系，按需准备入口 |
| 等待 | async 提交后返回；sync 等最终结果；显式等待超时只结束本次等待 |
| 连续性 | 保存任务、消息、结果和 Inbox；恢复后继续跟踪原操作 |
| 管理操作 | 在适配器实际支持的范围内查询、取消或停止操作 |
| 源码上下文 | 识别选定源码位置，提供工作区视图和固定版本视图 |

普通任务可通过结果和协作判断完成。项目可以另外选择 Review 或接受规则。
成果文件、日志、commit 和测试结果可以附在任务上，作为后续协作资料。

## 状态的必要范围

### 持久配置与记录

- 安装者身份、已确认机器、连接设置和项目路径。
- 已确定的项目及成员关系。
- 任务目标、请求身份、消息、结果和协作决定。
- 历史源码快照、Review 和接受记录。

这些内容跨重启保留，通过用户明确变更或对应协作命令更新。

### Runtime 自动维护

- 网络连接、会话进程、接收入口和实时可用性。
- 重连、重试、时钟校准、操作中的临时锁。
- 操作需要的内部凭证和进程代际。

这些内容表达即时事实。旧观测过期触发重新探测与恢复；恢复结果决定
当前操作状态。重启保留长期配置，并重新建立真实存在的执行关系。

### 用户可见状态

用户主要看到任务是否已接收、执行中、等待结果、完成、失败或取消，
以及目标机器是否正在连接、在线或离线。身份认证问题、网络故障、
Harness 错误和任务冲突分别报告，并给出自动恢复进度。

## 单安装者的默认权限模型

服务入口确认安装者或其有效连接凭据。机器和项目访问继承安装者已确认的
配置。Root、Route 和任务职责用于组织协作；日常职责配置直接建立所需关联。
Core 在命令执行时校验请求属于对应项目和操作对象，维护结果完整性。

长期信任通过显式撤销、重新绑定或配置变更结束。内部临时连接凭证的维护
属于连接服务责任。外部平台要求账号重新登录时，给出具体的登录指引。

多用户委托、逐职责权限隔离、强制职责分离、限额和额外审批属于可选策略。
已有共享部署在迁移前保留原有访问边界，并单独决定策略映射。

## 可选策略和专用能力

- 项目要求独立 Reviewer、指定 Finalizer 或发布审批。
- 项目要求固定候选快照、证据摘要、测试覆盖和接受门槛。
- 共享服务要求多用户隔离、逐角色委托和独立限额。
- 特定执行需要受保护资源入口或操作系统级隔离。

策略按项目或部署明确启用，适用于其声明的操作。
历史记录保留其形成时间、参与者、当时权限和对应候选。其内容有效性
与当前会话在线状态分别判断；撤销历史记录或调整信任有独立的明确操作。

## 外部 Harness 的控制边界

Core 记录职责并通过适配器提交操作。其控制承诺以适配器实际覆盖的范围为准：

- ACS 启动并持有的进程可以在具体平台的控制机制下管理其生命周期。
- 已有外部会话按照 Harness 原生 API 的实际能力接入。
- 专用资源网关可以约束经过该网关的操作。
- Harness 直接执行的 Shell、文件写入和外部调用遵循其自身运行环境。

角色标签、任务限制和内部 Lease 分别说明用途及覆盖范围。对完整文件系统、
网络或整个外部 Harness 的隔离承诺，须由实际覆盖的操作系统机制支持。

取消结果区分“请求已提交”“停止已确认”和“执行状态待确认”。
若调用已经执行但响应丢失，Core 查询同一请求的状态，避免重新发起已完成操作。
该保证针对 ACS 的提交与跟踪路径；外部系统中的业务副作用按实际接口处理。

## 清理对象的定义与判定

### 定义

**应清理机制**：在 ACS 默认单安装者协作路径中，增加操作门槛、状态依赖或
持续维护负担，却不能说明其直接支持的协作结果、实际生效范围和保留必要性；
或者把可选项目策略、部署策略和 Runtime 维护强制变成日常使用的前置条件。

核心协作结果包括任务正确投递、执行入口可用、消息和结果对应、避免重复提交、
协作记录可恢复，以及用户已选择的职责和流程得到执行。

一项机制的价值需要用其实际阻止的失败场景和覆盖路径说明。
具有安全、证据、授权等名称本身不能证明其应进入默认 Core。
无法确认实际作用时标记为待核查，补足依据后决定处理方式。

### 清理类型

| 类型 | 判定条件 | 典型表现 | 处理方式 |
|---|---|---|---|
| 控制范围不成立 | 声称约束的操作可以在其覆盖路径外发生，实际边界未覆盖该操作 | 内部 Grant 或 Lease 被描述为能控制整个外部 Harness 的文件写入 | 删除超出覆盖范围的承诺和相应默认门槛；保留真正生效的局部能力 |
| 临时状态成为长期使用资格 | 临时观测或登记到期使已保存的机器、项目或协作关系无法继续使用 | 通道实际可达，陈旧登记却让机器不可执行 | 分离长期配置与实时事实；使用时探测和准备执行入口 |
| 内部维护转交调用者 | 常规重启、重连或会话替换需要用户或调用 Agent 修复内部记录 | 要求手工续期、重新登记，或查找并运行 Shell 修复命令 | 将维护纳入 Runtime 生命周期，提供自动恢复及明确结果 |
| 同一判断重复实现 | 同一操作、对象、权威来源和版本下，重复计算相同判断且未跨越新的执行边界 | 一次调用内反复扫描同一授权链或读取同一组能力记录 | 合并计算和复用当前操作的结果，保留真正跨边界的检查 |
| 可选策略强制进入默认路径 | 普通协作必须满足某类项目或共享部署才需要的约束 | 每项任务都要求独立评审、证据包、逐角色授权或独立预算 | 移至明确启用的项目或部署策略 |
| 历史记录依赖现役状态 | 已形成记录仅因参与者会话退出或权限自然到期就失去正常使用价值 | 测试和 Review 已完成，参与者不再在线导致无法继续接受 | 保存形成时的事实与候选关系，分别验证当前决定和明确的失效事件 |
| 多份记录表达同一事实 | 同一可用性由多份需要单独维护的记录表达，缺少清晰的唯一来源 | 一个通道要同时维护若干含义重叠的到期状态，最早到期项阻断整个路径 | 确立事实来源，派生查询视图，合并重复生命周期 |
| 产品状态表达失真 | 错误或摘要状态不能对应真实原因，并促使调用者采取错误操作 | 命令过期、网络离线和权限撤销都报告为授权失败 | 按实际原因返回状态和恢复动作，简化用户可见流程 |

同一机制可以命中多个类型。清理按触发点和职责处理，而不是按名称整块删除。
跨队列派发、重新取得资源或产生外部副作用时，状态可能发生变化；这些执行
边界上的再次确认不能仅因检查内容相似就判为重复。

### 四种处理结果

1. **删除**：没有实际价值的门槛、重复事实和超出覆盖范围的能力承诺。
2. **移出默认 Core**：有明确用途、适用于特定项目或部署的策略和专用能力。
3. **合并**：相同事实来源、相同操作上下文中的重复计算和状态维护。
4. **自动维护**：连接、会话和执行准备所必需的运行职责，由 Runtime 承担。

自动维护适用于仍有功能价值的运行状态。对于重复或缺乏用途的登记，
单独增加续期程序不能完成设计清理。

### 每项机制的审查记录

每个清理项记录以下内容，供实现者直接执行：

- 所在模块及触发条件。
- 直接支持的用户协作结果。
- 能实际阻止的失败，以及真实覆盖范围。
- 给正常协作带来的等待、配置和维护负担。
- 删除、移出、合并或自动维护的具体决定。
- 改造后的用户路径，以及证明协作结果仍正确的验收场景。

服务入口身份确认、项目与操作对象定位、请求与结果对应、提交去重和
协作记录恢复属于 Core 基础职责；实现仍需接受相同的覆盖范围和负担评估。
共享部署的访问边界按其部署要求另行评估。

### 清理完成标准

正常路径能够直接完成任务提交、执行、结果读取和继续协作；所选择的
可选策略按其适用范围执行。用户和调用 Agent 的必要步骤减少，错误能够
对应真实原因，原有任务、结果和项目关系保持可用。

验收同时检查功能结果和用户步骤。仅调整错误名称、延长到期时间、自动填充
证明字段，或者将同一门槛迁移到另一模块，都不足以证明清理完成。

## 实现迁移清单

| 当前实现 | 整改方向 |
|---|---|
| 连接登记与 Endpoint 有效期汇总成 expired | 连接状态、登记刷新和真实执行就绪分别维护；自动恢复到可用入口 |
| 无当前 Harness 记录时无法完成派发 | 根据请求和已保存设置准备会话，再执行实际调用 |
| 多层临时登记成为常规操作前置条件 | 稳定机器配置与运行绑定分开；常规运行绑定由连接 Runtime 维护 |
| 逐角色 Grant、预算和严格接受校验进入通用路径 | 单安装者默认使用持续信任；可选策略在启用边界执行 |
| 多种故障汇入 AuthorizationDenied | 根据失败来源返回明确类型及恢复动作 |
| 工具发现和一次调用重复查询授权链 | 批量计算可见能力，实际操作保留入口身份与对象检查 |
| 当前参与者权限寿命影响历史证据接受 | 保存历史形成事实，单独验证当前接受决定和项目策略 |
| 普通开发读取依赖干净提交快照 | 提供明确标注修改状态的工作区读取；固定快照用于选择的评审流程 |
| 外部 Harness 控制依赖内部标签和登记 | 用原生适配器与实际进程控制提供能力，并准确返回控制覆盖范围 |

先实现机器连接和会话准备的最小执行路径，再迁移消息与结果跟踪，
最后拆分可选策略。保留既有项目、任务、消息和历史结果。
策略迁移按部署进行，已有共享服务的访问关系须有明确映射。

## 验收场景

1. 首次配置一次机器后，本机与网页 Agent 可以对该机器提交实际任务。
2. 目标机器重启后，连接自动恢复，原项目身份和任务记录仍可使用。
3. 一段时间未使用后，下一次任务自动准备入口并执行。
4. 当前没有活动 Harness 时，按请求启动新会话并返回结果。
5. 网络中断和重连过程中，保留同一消息与执行关联，避免重复提交。
6. 本机收到的执行结果可以由网页会话读取，反向同样成立。
7. 普通工作区修改可读取；Review 可以选择确定的候选快照。
8. 普通任务可完成；启用 Review 策略的项目按选择的职责完成评审和接受。
9. 外部会话的停止能力与原生 API 一致；返回的控制状态可以解释。
10. 自动恢复无法处理的故障给出具体原因；仅必要的账号登录、新增访问授权
    和项目决策交给用户，配置和常规恢复由系统完成。

## 核对过的实现入口

- `runtime/project_service.py`：项目授权、工具发现、连接状态和命令有效期。
- `runtime/project_management.py`：成员与 Harness 执行入口查询。
- `runtime/domain.py`：Grant、委托链、接受和证据校验。
- `runtime/codex_driver.py`、`runtime/opencode_driver.py`：原生会话与进程控制。
- `runtime/effects.py`：专用文件资源保护入口。
- `scripts/acs_startup.py`：现有 Core 与传输恢复；执行登记准备仍需另行闭合。
