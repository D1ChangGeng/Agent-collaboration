# Project and Route decision map

| Question | Durable object |
|---|---|
| Which product or data boundary? | Project |
| Which shared identity and Route registry? | Collaboration Root |
| Which long-lived goal or architecture line? | Route |
| Which knowledge and collaboration boundary? | Scope |
| Which acceptable unit of work? | WorkItem |
| Which current reasoning instance? | Authenticated external Session responsibility projection |

Create a Route for a durable line with its own goal, decisions, knowledge or
source relationship. Create a WorkItem for a concrete deliverable within a
Route. A new window, machine, Session, branch or retry preserves existing
identity.

Select Project context using project_id and resolve all supplied handles in
that same tenant and Project. Read the installed access mode when a decision
depends on admission: owner uses continuous trusted identity and explicit
revocation; shared adds configured Grant, Policy and budget checks.

Use current workspace context to understand active local changes. Use an exact
view revision or committed snapshot for delegation, Review and reproducible
acceptance. A changed instruction or source view requires refreshed context
before an action that depends on it.

Cross-project analysis keeps separate Project IDs, Authorities, revisions and
evidence. Create explicit relationships or WorkItems for coordination in each
affected Project.
