# Source and evidence decision map

Select a reader from the available Native, Git, repository MCP and other Agent
tools. Choose the capability that can observe the intended location and record
the provider, repository, branch, commit/tree, workspace state and view identity
actually used.

For ordinary owner context reads, resolve the Project product Source from
primary_source_id or its eligible product hints. primary_source_root names the
preferred repository read location; default reads resolve its physical primary
worktree and actual current branch. Use explicit source_root to select another
configured readable current worktree. Choose the execution Node separately.

Treat versions and origin_hint.host/path as guidance. Use current_readable_root
for the Core filesystem location and actual_source for the captured readback.
Review its provider/root/commit/tree/view_revision/observed_at together with
the observed branch and workspace state.

Keep product source_observation and distinct management_source_observation
attached to their own context. If the product default is unavailable, its
observation and primary/version-hint references are null. Management instructions
and explicit management reads retain their purpose and access checks.

Choose a fixed commit or captured workspace view explicitly when reproducible
bytes are needed. Routine context follow-ups use current views with version
hints. Pagination uses the returned view_revision; a new current read can
observe newer edits.

Review and acceptance retain the actual candidate and source/evidence identity.
Record commits, Push and receiver action independently of Message delivery.
Current access and explicit revocation checks govern new reads. Shared
deployments preserve their existing Scope, permission and version boundaries.
