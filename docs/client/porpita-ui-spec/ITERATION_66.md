# 第 66 轮 · 在原 Host 核对保留分支

接续已通过的第 63–65 轮。用户从配对主机删除工作区后，可由原有保留分支通知进入复核。沿用 Space 已确认的对话框、行内「核对检出」、等宽路径、键盘焦点和 Git 状态样式。始终显示该条分支的仓库与 Host，打开复核时从零选开始。

Space 的容量扫描按当前进程的文件系统能力生成结果。配对 Runtime 的分支证据来自动作所属 Host 的工作台复核。核对以删除回执保留的 Host、仓库、工作树、分支和 HEAD 为依据，通过同一条配对通道在原主机查询引用与工作树列表。网络上的另一台主机和当前机器可以有同名分支及相同 HEAD。 [Git 工作树列表](https://git-scm.com/docs/git-worktree)

沿用已有的配对 Runtime 工作区权限，服务端先找待清理记录，再执行只读 Git 命令。已登记工作树的跨窗口定位仍走 Space 的实例校验。配对端复核行提供 Host 与检出路径，用户在所属主机查看工作树。只提供 SSH 记录且工作区尚无所属 Runtime 服务时，进入既有的主机接入流程。对应 M.02.25。 [回放工具](tools/observe-space-remote-checkout.cjs)

英简中回放以同机两个独立进程配对，实际删除 Studio 工作区并在原仓库移动检出。本机镜像了一条同名同 HEAD 的分支。按 Enter 核对后，界面显示 Studio 的路径，两条引用保持。 [英语画面](evidence/iteration-66-68-paired-en/i66-paired-host-checkout.png) · [简中回放](evidence/iteration-66-68-paired-zh/run.json)
