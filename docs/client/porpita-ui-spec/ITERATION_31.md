# 第 31 轮 · 端口等待、失联和恢复

选择变化时原端口弹层结束，重新打开时按当前来源读取。已读结果绑定工作树根、Host、配对版本与连接代次。扫描经现有 RPC 携带配对版本。等待沿用原端口状态图标，减少动态时保持静止。

| 条件 | 状态栏与弹层 |
| --- | --- |
| 当前工作树尚未读取 | 保留端口入口，计数待读 |
| 正在读取 | 显示当前 Host 和检查状态 |
| 成功 | 显示当前工作树的监听项与数量，合法空结果显示 0 |
| 读取失败 | 显示该 Host 的读取失败，保留刷新 |
| 暂时失联 | 显示原 Host 离线 |
| 配对撤回或工作树不可确认 | 显示工作树端口不可用 |

先读 Studio 的实际监听项，停掉 Studio 后核对离线状态，再替换测试服务的端口。重连后重新打开原工作树范围，检查新端口和旧结果退出。撤回配对后核对不可用状态和工作树动作退出。对应 A.03.07、G.05、S.06、J11 和 J12。

最终回放通过完整的停止、重启与设置撤回。原弹层在连接状态切换时收起。Studio 目录恢复后重新打开端口，验证新监听可见、旧监听退出。本机端口在 Studio 停机时仍能读取。 [断线连续帧](evidence/iteration-30-32-ports/ports-host-outage/timeline.json) · [重连结果](evidence/iteration-30-32-ports/i31-ports-recovery.png) · [撤回画面](evidence/iteration-30-32-ports/i31-ports-revoked.png)
