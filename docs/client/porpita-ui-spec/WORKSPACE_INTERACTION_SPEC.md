# Session、Workspace、Pane、Top-level Tab 与 Tab Group

显式启用的 Windows 开发预览可组合本机与配对 Runtime 的 Chat，也可保留固定范围的 Explorer。工作台搜索、侧栏目录与 Vault 原位动作按真实来源进入已打开的 Workspace。顶层分组支持菜单和拖放。日常工作台的内容 Tab 与 split tree 对应 Worktree。 [第十三轮](ITERATION_13.md) · [跨 Host 组合](ITERATION_21.md)

| 对象 | 用户职责与权威 | 持久化与呈现 |
| --- | --- | --- |
| Native Session | 直接操作的 Harness 对话或 Agent 执行。由 Harness/Host 决定原生输入、工具、审批和历史 | 稳定 Porpita 引用 → Provider/Harness namespace + 持有者/Host + 原生 Session ref；generation 单列，重启只换代次。身份映射不参与去重 |
| ACS Conversation | 经授权项目范围的通信、回复、附件及投递回执；ACS Core 决定可见和授权范围 | 独立会话与消息引用，原生来源能验证时提供跳转。ACS ACK、原生接纳、任务执行、回复分别呈现 |
| Porpita Workspace | 用户维护的工作布局，可包含跨 Project/Route/Host 的 Session 和 SidePanel | workspace ID、用户名称、open/closed、当前叶与恢复指针、split 树/比例、内容引用和各视图状态；按 profile 保存 |
| Pane | Workspace 中的叶与焦点容器；呈现一个 active item，可保有其他内容项 | pane ID、active item、顺序和最近访问；保留 Orca 的内容路由。空 Pane 可选目标；不可用保留引用与位置 |
| Top-level Tab | 一个已打开 Workspace 或独立 SidePanel 的唯一入口 | 以对象类型 + ID 唯一，保留 group、排序、固定与最近激活；内容 Tab 没有顶层身份 |
| Top-level Tab Group | 用户整理顶层工作对象用；不参与布局、运行、权限 | 稳定 group ID、名称、顺序、用户是否选择过；General 是未指定组的明确归处 |
| SidePanel Definition / Instance | Definition 声明可用 scope、宿主模式与状态接口；Instance 持有具体 scope 和持久状态 | instance ID、定义 ID、显式 scope、当前呈现位置、内部 Tab 和 view state；唯一可交互宿主；详见 [能力矩阵](SIDEPANEL_CAPABILITY_MATRIX.md) |

同名、同 Identity 或同项目的会话仍独立。无法关联的历史记录可继续在 Vault 阅读；须有可信的原生引用才能被选作可交互 Session。回放夹具要包含同 Identity 的两个 Session、同名分支的两个 Host、无 Project 的 Session 和含多项目的 Workspace。未授权对象不可被搜索结果或计数泄露；离线但仍授权的已知对象可显示最后更新时间和可读历史。

现有工作台的历史路径分三步。搜索或展开行用于查阅，行尾的定位按钮回到唯一的原 Chat 或终端 Pane，恢复按钮针对有可用恢复路径的历史。Tab 已关闭或目标身份有冲突时重新计算操作。会话名称和消息片段用于查找，Host、原生会话 ID、已知记录路径和当前 Tab/Pane 共同限定回源。结构化会话按记录的 Host 路由；已打开终端用已确认的 leaf 交回输入焦点。 [第四轮](ITERATION_04.md)

Vault「所有主机」结果在单条和多条时都显示来源。每个索引独立返回结果和状态，配对端不可达时按用户配置名提示并在当前位置重试。重复的原生 ID 用 Host 与来源记录分别定位。撤回来源时由原 Host 重新裁定记录可用性。 [第五轮](ITERATION_05.md)

工作台跳转面板的「搜索会话历史」将当前查询交给 Vault，并聚焦其搜索框。用户在原工作树持续查阅，由明确的定位或恢复动作决定后续位置。在右侧 Dock 可用的页面显示入口；工作台创建视图与独立功能页按既有 Dock 可用性决定。 [第六轮](ITERATION_06.md)

命名分离从控制的实际对象开始：现版「创建工作区」会建立或打开执行环境；新增布局入口应称「新建工作空间」。协作弹窗的现有「工作区」下拉实际选择 ACS Project（`CollaborationButton.tsx` 取 `project_id`）；目标称「协作项目」，与 Workspace 内固定范围的 Panel 区分。既有“活动”“历史”“项目”各有自己的导航和搜索结果类别。

## Session Index：发现、判断、打开

预览工作台的「会话」目录列出本机和已配对 Runtime 的已开 Native Chat。位置可选所有工作树、当前工作树或已打开的工作空间，分组按最近或项目，并可独立选择 Host。行显示 Harness 和来源，已在 Workspace 内的本机或配对 Chat 可进入对应 Pane，其余可打开原 Worktree。选择成功后将输入交给目标 Composer，返回时保留本次运行的目录条件。已关闭布局通过工作对象列表找回。 [第十五轮](ITERATION_15.md) · [第二十轮](ITERATION_20.md) · [第二十一轮](ITERATION_21.md)

「搜索历史会话」把查询文本交给右侧 Vault。用户选已绑定的本机 Chat 的原位动作时，可以进入当前打开的 Workspace 与具体 Pane。打开普通 Worktree、终端或其他 Host 的历史继续使用各自的原位流程。 [第十七轮](ITERATION_17.md)

「未打开的历史会话」复用 Vault 的扫描、搜索及明确恢复动作。已确认原 Pane 的记录留在已开目录或完整历史。原生运行图标从所属 Host 的会话投影读取。协作入口进入原授权项目界面，由原消息记录决定能否检查投递与打开来源。 [第十八轮](ITERATION_18.md) · [第十九轮](ITERATION_19.md)

以下规则用于完整 Session Index，覆盖统一 Session ref、跨 Host Workspace 与多来源状态。

- Sidebar 顶部保留搜索和辅助页；工作对象区提供「会话」「项目」「活动」切换。复用当前项目行、虚拟列表、折叠标题、搜索框与上下键语义。每行一条名称主线；次级显示 Identity/Role 与 Harness，Host/Project/Route 作为可展开详情或分组标题。未读和需要处理同时出现时，优先显示可执行的审批/问题，不遮盖断线。
- 会话状态有三个独立来源：**运行**（就绪/执行/等待输入或审批/停止/未知），**通信**（未读/投递阶段/待确认），**Host**（可用/连接中/断线/未知）。Needs Attention 由待处理原生输入、未读协作和需用户干预的恢复组成，可筛原因；已运行不等于需要注意。标为已读只写其来源，不结束运行。
- 「全部」「活跃」「需处理」「收藏」「未分配」是筛选；Group By 一次只选 Recent/Project/Route/Identity/Harness/Machine，其他条件可叠加。全局筛选、查询、折叠与滚动保留；「在当前工作空间」是显式筛选。区分首载、无会话、无匹配、没有授权的可用对象、Host 离线和部分数据；无匹配给清除筛选，未连接给恢复入口。
- 单击/Enter：若已有交互呈现，激活对应 Workspace 和 Pane（包括非当前组）；未打开时加入当前 Workspace 的焦点 Pane 并激活，原内容保留在该 Pane；没有 Workspace 或当前是独立 SidePanel 时建单 Session Workspace。单击不销毁内容或打开后台运行。双击在同一稳定对象上仅聚焦，不重复创建。明确命令：「在新 Pane 打开」「在新工作空间打开」「定位已打开工作空间」；已在别处时，前两者改为明确的「移动到…」，支持取消。
- 拖动与键盘菜单共享目的地。中心将引用加入目标 Pane 并选中，边缘创建同方向 Split，保持原内容。非交互历史/无授权/空间不足时不可提交，反馈具体原因；Esc 或在目标外放手取消，源位置和焦点保持。当前显示已打开的位置；筛选不改变对象归属。

选择「加入而保留旧内容」是对参考包“焦点 Pane 打开”的细化。对照候选为替换当前内容或每次新建 Split；第一种容易打断并行工作、第三种会快速吃掉窄窗空间。利用 Orca 已有多内容 Tab 的保留行为是首选；必须用有草稿和正在运行的会话在真实宿主复验。

## Workspace：创建、组合与恢复

| 触发 | 状态变化与反馈 | 必须保留 |
| --- | --- | --- |
| 新建工作空间、从任务/会话打开 | 确认布局 ID 后创建顶层 Tab；无内容时显示选择会话/工具；默认命名取首次内容/来源，已命名后不随内容改变 | 原生对象的执行、访问和来源；创建失败停在原处 |
| 切换顶层 Tab / Pane / Pane 内内容 | 同步更新选中和焦点样式；保留后台内容与滚动；未就绪只在该目标显示占位 | 当前键盘目标、各自草稿、滚动、文件 owner；切换不会发送内容 |
| 从源移动到目标工作空间/Pane | 先检查 scope、视图状态、可接受尺寸及未保存守卫；原子提交目标引用与源移除，失败回滚到源 | 一条输入路由、相同引用、已运行会话、文件编辑状态与 scope |
| 拆分、拖宽、最大化、恢复 | 拖分隔条直接映射比例，松手才持久化；提供键盘调整与重置。最大化只覆盖显示，回退恢复相同树和焦点 | 隐藏 Pane 不结束执行；短窗无法满足内容最小尺寸时拒绝新分屏，已有布局允许临时聚焦呈现 |
| 移除 Pane 内容 / 关闭 Workspace Tab | 移除的是呈现引用；选同 Pane 最近内容或邻 Pane。关顶层 Tab 后按组内 MRU、邻组或入口恢复焦点 | Session、原生历史、后台运行、可恢复布局和支持持久化的草稿 |
| 删除工作空间 / 结束会话 | 删除布局列明对象，不删除 Session/Panel definition；结束会话只能由原生有权操作触发，运行中保留确认 | 正确目标和现有权限；不可操作时提供解释 |
| 再开、重启、Host 断开恢复 | 还原最近工作对象、组、Pane 树、选择和尺寸；读取失败/权限撤回呈现受限占位或安全移除；恢复单个对象时检查 generation | 先恢复可读布局，再允许有权输入；部分失败不阻塞可用 Pane、不重新启动任务来填空 |

已在现有 Worktree 内容分屏验证可复用规则。分隔线提供方向、键盘焦点和比例，每次方向键调节 5 个百分点，Home/End 跳到支持范围端点。拖动预览直接调整 Pane，释放才写给布局 owner；Esc 和 pointercancel 回到手势前比例。目标 Workspace 的内容最小宽高、聚焦呈现和跨 Host 组合按目标树验收。 [第七轮](ITERATION_07.md)

桌面主进程保存预览布局，包含组、打开对象、会话引用、比例和 Explorer 的固定 Scope。用户在普通退出并重新启动后从预览入口继续上次工作。原生会话和草稿由原组件恢复，文件列表重新读取原目录。 [第十二轮](ITERATION_12.md)

会话引用绑定 Host、配对版本、Worktree 和原生会话身份，恢复所选 Pane 时使用同一组身份。读取 v1 记录时为会话补本机来源。当前布局格式为 v3，新增 Explorer 的来源限定。读取 v1/v2 时将原 Explorer 解释为本机范围，下一次布局编辑保存 v3。同一配对的 Runtime 短暂失联时可在原 Pane 恢复，另一个 Pane 仍可编辑。来源撤回后显示失效引用，移除只作用于 Workspace 布局。 [第二十二轮](ITERATION_22.md) · [第二十三轮](ITERATION_23.md) · [第 26 轮](ITERATION_26.md)

源复用：`TerminalTitlebarTabs.tsx` / `tab-bar-surface.tsx` 负责旧 Tab portal 和溢出；`TerminalWorktreeSplitSurface.tsx` / `TabGroupSplitNodeTree.tsx` 负责 worktree scoped split；`tab-types.ts` 的 `TabContentType` 已有 terminal/editor/diff/conflict/check/graph/agent-session/browser/simulator，含 worktree 和可选 executionHostId。**首选独立的用户布局 owner + 保留 content owner，复用 split 渲染与输入动作**。直接将 worktreeId 改名、把通用 SidePanel 塞入现有内容类型或用 `activeWorktree` 做全局 fallback，都会让文件、PTY、审批或宿主退役出现错绑；只有类型扩展和生命周期实测均成立时才推进复用范围。PTY 分割与布局分割保留各自既有语义。

## Top-level Tab 与分组

一行标题栏使用组选择器、当前组 Tabs 和可全组定位的打开列表。沿用 Orca Tab 选中线、横向溢出、关闭与键盘焦点；保留系统窗口控件。选择器全名在菜单和可访问名称中可读，视觉宽度按 132px 与标题栏可用宽度的 31% 取较小。小于 260 CSS px 由打开列表提供溢出补偿。切组恢复其最近仍打开的对象；空组提供打开入口。拖到选择器后选择目的组才改变归属，键盘走同一菜单，默认留在源组。240/420/920 CSS px 的浅深色及真实键鼠已通过组件试验。生产窗口、持久化、IME 与读屏仍按 J03/J06/J13。 [分组 Shape](GROUP_TRIAL.md)。

新对象只在创建时推荐组：可由主要 Project 提示，跨项目或无归属落 General/当前显式组。已手动调整后保持不变。组菜单支持创建、重命名、移位和删除；移动可以拖拽或菜单选择。删除组前明确其 Tab 的去向，默认全部移到 General；始终保持对象打开及焦点，不调用 close。若一条内同时显示多个组才提供折叠；折叠后用按钮可展开且能找到活跃项。固定 Tab 不参与批量关闭；固定是否跨组可见保持组内，溢出全局按组搜索。名称可重名但条目用图标/上下文区分，组重复名称提示。各层分别有键盘可达目标与可识别名称；默认不抢占现有 Ctrl+Tab 的内容 MRU。

窗口初代建议一个 profile 的主工作窗口拥有可交互布局；Dashboard/Space 保留各自独立窗口。多主窗口扩展前须验证输入租约、动作归属和恢复冲突；观察镜像为后续可能能力。退出和多显示器回归不等同于两主窗口已实现。

## 控件与状态规则

独立 SSH 工作树的操作从原工作区进入对应 SSH 设置。原主机卡片承担连接与接管反馈，服务确认迁移后，工作区沿原项目标识进入托管服务。直接访问链接创建的配对和 SSH 接管创建的服务分别显示，各自使用真实运行身份。接管后，保留分支的核对和删除继续绑定到该工作树的所属服务。 [实机配对](ITERATION_72.md) · [SSH 接管](ITERATION_73.md) · [分支复核](ITERATION_74.md)

键盘焦点在 Worktrees 列表中时，删除快捷键使用列表当前项，并按实例及 Host 校验。连接中的主按钮保持可定位，状态变化留在本行。Linux 工作台用 Alt+T 到达通知，再在复核对话框内操作。检查、恢复与重试期间，原行持续提供状态与后续动作。 [键盘接管](ITERATION_76.md) · [Linux 复核](ITERATION_77.md)

共享形态见 [视觉与交互规范](VISUAL_INTERACTION_SYSTEM.md)。默认保留 Orca 的 280px 左栏和现有标题栏关系。Pane 顶部只出现当前所有者名称/动作；侧栏、顶栏和 Panel 内导航的选中记号必须能同时看懂。任何等待保留壳体和已知内容：新对象显示加载，Host 断开显示范围/重连，失去权限不露旧数据，终止保留合法历史但禁用输入。焦点进入按当前内容的原生首选控件；键盘导航和拖放均可撤销到可用焦点；Escape 优先由最高层弹出面消费，终端/编辑器继续拥有内部快捷键。阶段试验见 J03–J07/J13。

**短窗。** 已实现的 Shell 在普通桌面尺寸保留 320 CSS px 主区。两侧栏无法同时保持最小宽度时只显示最后明确打开的一侧，焦点若失去原控件则回到对应开关。变宽恢复用户宽度和打开偏好；Explorer 临时隐藏时保留查询。目标独立布局按活动内容计算可用空间，支持短窗口聚焦呈现和恢复，保留 split 树、比例与焦点。详细门槛、Chat/终端分割和未测条件见 [第二轮布局](ITERATION_02.md#工作台宽度)。

Explorer Dock 的文件名筛选按工作树、文件操作 owner 和显示根保留在本次应用运行。切换 Dock 工具或工作树后，回到原范围时重新读取匹配项。独立 Explorer 与嵌入 Explorer 采用下面的实例约定。 [第八轮](ITERATION_08.md) · [SidePanel 能力矩阵](SIDEPANEL_CAPABILITY_MATRIX.md)

## SidePanel：固定 Explorer 与会话并行

| 配对撤回 | 失效占位隐藏旧标题、路径、查询和文件行，并显示「移除资源管理器」。 | 从布局移除该引用后，原 Workspace 和其他实例仍可继续。 |

## Workspace 状态栏的用量

打开组合式 Workspace 时，当前 Agent 用量取自所选 Chat 的 Host。Chat 的来源需要通过原配对和会话校验。进入嵌入 Explorer 筛选框时仍沿用所选 Chat，独立 Explorer 使用文件范围。设置、普通工作树和原编辑器各自使用本身的来源。

用量组件显示 Host 名称。空态与用量入口可进入该 Host 账户设置，返回保留原布局和所选 Chat。读取等待、Host 离线、账户快照不可用及配对撤回分别呈现。Host 恢复时读取新快照。选择或配对发生变化后，不同来源的旧菜单、读数和操作入口不再显示。 [第 27 轮](ITERATION_27.md) · [第 28 轮](ITERATION_28.md) · [第 29 轮](ITERATION_29.md)

## 工作树的端口与桌面资源

Workspace 的端口入口使用所选 Chat 的工作树。独立 Explorer 使用自己的固定工作树，嵌入 Explorer 的焦点保留所选 Chat 的归属。弹层注明 Host 和工作树。打开或刷新读取该工作树的监听项。待读、失败、离线和撤回各有状态。转到原工作树以操作端口，返回继续原 Workspace。 [第 30 轮](ITERATION_30.md) · [第 31 轮](ITERATION_31.md)

预览资源管理器单独标明本机汇总与本机 PTY，项目树仍按项目来源呈现。切换所选 Chat 时资源汇总仍是桌面所在设备的读数。 [第 32 轮](ITERATION_32.md)

端口详情显示 Host、工作树、监听地址、进程和诊断依据。本机另列实际 Browser URL。打开前确认同一监听和 URL。监听已变时可直接刷新，焦点进入同一工作树的端口列表，等用户再选目标。配对 Host 的端口操作经原工作台入口。 [第 36 轮](ITERATION_36.md) · [第 37 轮](ITERATION_37.md)

资源管理器的工作树行可定位原工作台，Browser 行可进一步恢复原分组、原标签和活动页。目标可定位时完成视图交接，再次打开预览保有原已选对象。浏览器行的成本指标沿用已有资源模型。 [第 35 轮](ITERATION_35.md) · [第 38 轮](ITERATION_38.md)

已绑定的分屏终端行在标签名后按当前布局列出窗格编号。从预览回原工作树时，通过活跃 PTY 找到具体窗格，资源弹层退出后交接键盘焦点。绑定待确认、无标签或诊断暂时不可用的本机行保留详情和状态，刷新后继续当前有效绑定。 [第 39 轮](ITERATION_39.md) · [第 40 轮](ITERATION_40.md)

磁盘摘要的 Space 入口保留当前预览和扫描结果。开窗等待或失败时继续显示摘要，重试成功进入实际 Space。关闭 Space 后仍可继续原 Workspace。 [第 41 轮](ITERATION_41.md)

在本机 PTY 里，全选作用于当前可结束的终端。进入 Space 后，可通过图块或「查看目录」打开目录图，通过「返回工作区概览」回到概览。筛选保留项目选择，清理审阅使用当前可见且符合条件的工作树。 [第 42 轮](ITERATION_42.md) · [第 43 轮](ITERATION_43.md) · [第 44 轮](ITERATION_44.md)

Space 审阅初始焦点在「取消」。取消后回审阅入口，确认后回搜索框。Space 按同次确认的实际回执显示清理数量，保留项可查原因并在刷新后再次进入审阅。 [第 45 轮](ITERATION_45.md) · [第 46 轮](ITERATION_46.md) · [第 47 轮](ITERATION_47.md)

清理失败的工作树在原行显示实际阻塞原因。工作区移除数按最近一次确认计算。当前 Space 窗口内由审阅清理产生、仍由 Git 保留的分支单独计数，可以随时进入原分支复核。复核默认零选并聚焦取消。取消回入口，提交回筛选，Git 已确认删除的条目退出清单。 [第 48 轮](ITERATION_48.md) · [第 49 轮](ITERATION_49.md) · [第 50 轮](ITERATION_50.md)

分支删除使用原 Git 引用和已复核的提交。Space 在结果栏保留此批次的确认与退回信息。实际读到分支变化时，复核显示记录的提交和实读提交，该记录退出全选范围。用户可保留 Git 分支并结束此次复核记录。另一个工作树占用分支时可在释放后重新选择，使用原提交执行新的确认。 [第 51 轮](ITERATION_51.md) · [第 52 轮](ITERATION_52.md) · [第 53 轮](ITERATION_53.md)

Git 能指出占用分支的单一工作树时，在拒绝行提供检出路径。定位到同仓库、同 Host 的已登记实例可打开主窗口工作台，复核窗口及选择留在原处。外部工作树可按路径找回。释放占用后回到同一复核显式提交，随后按实际 Git 回执更新待复核项。 [第 54 轮](ITERATION_54.md) · [第 55 轮](ITERATION_55.md) · [第 56 轮](ITERATION_56.md)

主工作台确认打开工作树后，状态栏出现「返回 Space 复核」。它与仍打开的复核绑定，返回时焦点到原工作树按钮，按钮失效时走当前 Dialog 的「取消」。选择留在同一复核。提交、关闭复核或工作树辅助窗口失效时，主工作台撤下返回入口。 [第 57 轮](ITERATION_57.md) · [第 58 轮](ITERATION_58.md) · [第 59 轮](ITERATION_59.md)

原工作树按钮无法获得焦点时，返回动作由同一复核的「取消」接住。工作树目录失去对应实例后，行内显示「上次检出路径」及核对提示。同一路径重新登记的实例有自己的打开身份。用户明确提交时，当前检出位置与删除结果取该次 Git 回执。 [第 60 轮](ITERATION_60.md) · [第 61 轮](ITERATION_61.md) · [第 62 轮](ITERATION_62.md)

本机 Space 的检出拒绝行提供「核对检出」。以本次 Git 读数显示当前路径、未检出、分支变化或结果未确认。焦点和正常勾选保留在原复核，已确认 HEAD 变化的分支移出选择。用户明确提交后仍按当次 Git 回执处理再次占用或删除结果。 [第 63 轮](ITERATION_63.md) · [第 64 轮](ITERATION_64.md) · [第 65 轮](ITERATION_65.md)

配对主机的保留分支从工作台通知进入同一复核，按原主机返回的 Git 读数更新。暂时断线保留上次路径和勾选，恢复同一配对后可继续核对。提交被拒绝时返回未完成项并从零选开始。Space 的本机 WSL 项目在分支行标明发行版，使用该项目的检出路径和 Git 路由。 [第 66 轮](ITERATION_66.md) · [第 67 轮](ITERATION_67.md) · [第 68 轮](ITERATION_68.md)

配对断线及本机 WSL 停止均可在原行恢复并重新读 Git。未取得确认时保留该项勾选和上次路径，暂停含该项的提交。独立 SSH 通过原工作区对话框进入 SSH 设置，接入原项目后走所属主机的复核路径。 [配对恢复](ITERATION_69.md) · [SSH 设置](ITERATION_70.md) · [WSL 恢复](ITERATION_71.md)
