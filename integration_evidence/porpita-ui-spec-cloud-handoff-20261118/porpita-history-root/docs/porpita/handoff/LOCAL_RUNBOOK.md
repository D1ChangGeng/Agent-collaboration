# Porpita 使用说明

本说明对应 Windows x64 桌面应用。11 安装版的签名状态、摘要和实测范围见交付报告。

## 安装和首次启动

运行 `Porpita-0.1.0-windows-x64-setup.exe`。安装完成后，从开始菜单或桌面的 **Porpita** 快捷方式打开。托管协作服务随应用提供 Python、PostgreSQL 和 ACS；使用者不需要为此安装开发工具。Git 工作区使用 Git，普通文件夹可直接打开。

欢迎向导可以选 **Chat UI** 或终端。若要使用原生聊天、工具和协作唤醒，选择 **Chat UI**，再选择默认智能体。进入协作设置后，选择以下方式之一：

- **在此设备使用**：点击 **启动本地服务**，等待协作显示“已连接”。首次准备会建立 Porpita 私有存储。若覆盖安装后提示准备，点击同一个按钮；应用会先备份旧私有数据库，再启用该版本需要的存储。
- **连接已有服务**：输入 ACS 的服务地址与提供给你的用户连接密钥，再点击 **连接**。远端地址使用 HTTPS；本机服务可使用环回地址。应用会验证服务能力和用户身份，并在设置中显示实际版本。支持本机 Host 接入的服务可自动给原生智能体建立各自的可信连接。

在 **本机智能体** 点击 **准备智能体** 可启用随附的 OpenCode。已有可用登录时，应用会将登录准备到 Porpita 私有账户；若出现登录提示，先在原生 AI 提供商账户设置里登录。Codex 继续使用原生账户设置。按智能体自身的流程登录或选择模型。

## 工作区和原生聊天

在工作台选择 **添加项目**，打开现有仓库或文件夹，也可以创建一个新项目。通过 **新标签页** 选择 Codex、OpenCode 或其他可用智能体；终端、编辑器、文件、Diff、模型和权限依然使用工作台原有入口。原生聊天中发给智能体的输入、工具请求及审批都在当前 Chat 中处理。

## 协作消息与文件

点击工作台的 **协作消息**，选工作区和联系人。可直接发送、回复、搜索，或在发送前添加文件。没有 Run 或 Task 也可以通信。草稿与静音、归档、阅读状态属于你的账号。

消息的“存入收件箱”“原生输入已接纳”和“收到回信”分别描述不同阶段。在 **投递与来源** 中可展开具体状态和消息引用；**查看执行** 打开能够验证的原始原生输入。若状态需要核对，先检查原消息或待确认请求，保留同一个引用。接收端由宿主准备实际可读的文件；直接下载时应用会校验内容。

智能体使用自己的 `porpita_acs` 连接联系当前项目中的其他智能体。在 Porpita 启动的原生会话中，也可用随包 CLI 的 `orchestration --help` 查看命令。`/clear` 重置原生模型上下文；已有协作消息仍在协作历史中。

## 重连、升级和数据

可以在设置中的 **协作** 断开或重连。断开托管本机服务会停止本应用拥有的服务；连接已有服务的生命周期由该服务管理。重连后若设置页仍显示“重新连接”，关闭设置再打开可刷新连接状态。正常退出后再打开，原工作区、消息和已保存草稿继续使用原数据。关闭一个窗口时，后台行为取决于工作台设置。

Windows 默认用户数据位于 `%APPDATA%\Porpita` 对应的实际目录。私有服务、备份和诊断在其 `porpita\acs` 下；服务日志为 `service.log`。工作项目位于你添加或创建的位置。安装新版时使用 Porpita 安装包覆盖安装。卸载设置为保留用户数据与仓库；如要清理数据，先确认已保留需要的项目和备份。原 Orca 使用自己的安装和数据目录。

在 **设置 → 协作 → Orca 配置** 可主动导入旧配置。选择原配置的 `profile-state.db` 或 `orca-data.json`，完成后从配置菜单打开 **Imported from Orca**。Porpita 会复制项目、工作区和常用设置；随原配置找到的对应 Native 会话会以可读历史保留。需要继续执行时，从复制过来的工作区新开 Chat。两边仍引用你原有的项目文件，请按正常流程保存项目。

如只需要旧 orchestration 消息，选择 **Orca 消息历史 → 导入历史**，并指定旧消息数据库。用 `porpita orchestration inbox --legacy` 查看标记了来源的只读历史。
