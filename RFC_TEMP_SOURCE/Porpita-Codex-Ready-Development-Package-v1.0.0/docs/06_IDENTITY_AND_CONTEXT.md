# 06｜身份、项目与 Agent 上下文：内部完整，外部自然

## 保留核心语义

受信 Client 不等于任何无 Session 的调用者；Agent 作者来自其真实绑定。Project/Root/Route/Slot 保持现有模型，不把它们改成 Run/Task，也不为了客户端新增另一套管理层级。

用户在原生 Chat 输入是用户对 Harness 的请求，不是 Root 以自身身份发出了一条 ACS 消息。用户在协作消息入口发信显示真实 Client；模型调用 ACS 时才使用模型自己的绑定。

## 用户视角与内部映射

| 用户操作 | 内部行为 | 默认 UI |
|---|---|---|
| 打开已有仓库/工作区 | 复用上游工作区，选择或建立内部 ACS Project 对应关系 | 原有工作区列表，不新建组织树 |
| 启动 Agent | 原生启动；配置/接纳该会话的稳定协作者，建立受信 MCP/Receiver 链接 | 原有 Agent 标签与连接状态 |
| 与主 Agent 讨论项目 | 主 Agent 按已授权责任管理协作 | 原生 Chat，不显示 Root 技术表单 |
| 新增协作者 | 新建原生会话或关联已存在的会话；授权配置 Slot | 复用 New Agent/选择器，必要时一个协作选项 |
| 长期多线工作 | 按实际需要配置 Route；不按每个临时 Task 自动创建 Route | 工作区与 Agent 导航继续工作 |
| 结束/关闭会话 | 原生生命周期；稳定通信身份与历史保留 | 现有关闭/历史/恢复行为 |

Project 映射键优先用宿主真实工作区/仓库标识与服务 namespace，目录可移动；不要仅以路径字符串或显示名判定相同项目。一个真实项目可关联多个 worktree。把 scope、route、slot 等放在高级诊断，不强迫用户逐项配置。

## Agent 启动上下文必须真的交付

每个 Agent 获得：自身实际 ACS 地址、当前项目、已配置的上级/联系人、怎样查通讯录、统一 send_message、reply_to 原句柄、Inbox/等待入口。使用现有 ACS Skill/工具引导，控制篇幅，只传对当前协作有用的信息。

正常协作不要求理解 Run/Task/Dispatch 或新建任务。当用户启用可选编排时，宿主原有任务 preamble 仍可附加工作 ID；其中 send/ask/reply/check 改为 Porpita CLI/ACS 对应链。不得同时注入互相竞争的两套“唯一通信”指令。

模型持有的工具绑定必须由可信宿主配置完成；不能靠提示词说“你是 Root”替代权限。继承原生工具、MCP、shell 等能力，不把工程 Agent 降级成只读通信演示模型。

## 默认自动化边界

自动 provision 只在用户已选择项目与本地/远端服务、并具备相应权限时执行。现有管理者和成员关系优先复用。匹配不明确时让用户选择联系人/会话，不让其输入内部 ID。跨项目复用同一模型身份时仍保持实际隔离，不默认授予新项目历史。

## 首代完成条件

新项目能够在原有界面创建两个工作 Agent；它们无需人类复制上下文或手工编辑配置就能互相发消息。关闭后重开，稳定成员和消息历史保留。普通用户完全不需要理解授权版本、AgentSlot 数据表或 Route 生命周期。
