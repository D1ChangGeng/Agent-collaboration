# 00｜产品、范围与完成定义

## 产品定位

Porpita 是完整的 Agent 开发与协作桌面应用。其客户端形态直接继承 Orca，而不是将 ACS Core 的概念绘制成控制台。ACS Core 的职责是以通信为中心、客户端服务为辅助；不承担代码质量评判或通用任务状态机。

首代价值是：用户在熟悉的原生工作台中打开项目、使用不同 Agent、观察工具和代码变化；Agent 之间由 ACS 通信，用户可以看见相关交流并回到对应的原生执行。产品名、安装、设置与服务归属均为 Porpita。

## 必交范围

1. 以真实 Orca checkout 为基础的完整客户端，可构建、打包、安装、卸载与重新打开；不交独立仿制网页。
2. 原生 Chat/Terminal、分屏、工作区、文件/编辑器、Git/Diff、Provider 与模型/权限设置继续可用。见 feature-parity 清单。
3. Porpita 品牌、应用 ID、协议、用户数据、CLI、服务进程、安装产物与更新配置独立；保留合法署名和内部兼容符号。
4. 实际 ACS Core 服务接入、必要 schema/feature 采用、可信 Client 与每个 Agent 的独立绑定、正常 A2A 运输替换。
5. 真实宿主接收，普通发信/回复/后台等待、忙时消息、重开继续；不是在外部 Driver 中执行再把文本贴回 UI。
6. 现有 P1/P2 后端转为真实交互：联系人/消息历史、实时同步、阅读/草稿、搜索、文件分享；原生执行视图不重做。
7. 原生可选编排功能不中断：任务执行状态仍归工作流层，消息经 ACS；普通通信无需创建任务。
8. 最终安装版中的真实双 Agent、原生工具与审批、历史/附件和重开场景；功能证据能联系到当前产物。

## 完整性与平台边界

完整是覆盖已选桌面产品的正常端到端体验，不是承诺所有 Harness/OS/云服务组合都通过实验。默认首发为 Windows x64，依据既有 Windows 使用环境选定。继承的 macOS/Linux 源码和构建入口不得故意破坏；有 runner 时补对应产物，未实测平台列为未实测。

首代支持由 Porpita 宿主原生管理的 Harness；不要求为每个继承的 Harness 再建设一个 ACS 独立 Driver。实际跨 Harness 闭环至少包含 Codex 与 OpenCode；环境已有第二种可用 Harness 时可追加，不把全矩阵资格升级为完成前提。WSL/SSH 的 UI 形式沿用上游实际支持，不能宣传为原生结构化 Chat。

原生浏览器、预览、Git、远端工作区等保留。上游品牌专属托管服务/付费后台不是可凭源码复制的资源：保留能独立运行的能力，配置自有或用户服务，暂不可用的专属服务移除误导入口并明确列出；不得用它删除本地核心能力。移动 App 新分发、独立云 SaaS、计费系统不在本轮新增范围，已被桌面构建依赖的 web/mobile bundle 继续保留。

## 非目标

不开展新一轮 UI 创意探索、架构优劣研究、实验平台建设、泛化协议框架、独立设计系统；不重写已完成 ACS P0/P1/P2；不重做 Harness 推理、工具执行或 Git 工作区；不让新增负例/字段/状态机数量成为进度指标。

## 三个内部里程碑与一个最终出口

- M1：完整上游应用以 Porpita 身份启动并保留原生功能。它仍不是完成。
- M2：正常 A2A 全路径经真实 ACS/宿主，已完成客户端服务形成交互。
- M3：打包安装后功能体验通过，留下当前产物的证据。
- 最终 `PRODUCT_ACCEPTED`：M1–M3 完成，所有 required 场景通过，发布产物与运行说明可交付。只有变更记录/模拟 Host/开发模式运行不能签署。

产品开发允许迭代修复和必要测试。文档范围不得变成拖延进入应用实现的前置审查项目。
