# 09｜品牌独立化、服务归属与兼容命名

## 产品身份

应用可见名固定 **Porpita**；代码/CLI 默认 `porpita`；服务进程建议 `porpitad`。首个候选应用版本默认 `0.1.0`，与本开发包 1.0.0、ACS 包版本和 Orca 版本分离。已有合法版本序列则接续。

默认本地开发应用 ID 为 `io.github.d1changgeng.porpita`，是实施默认，不声称持有 porpita 域名。首次发布前在构建 manifest 固定真实 identifier；以后不随意改导致升级识别失败。

## 必须更改的面

`contracts/branding-map.json` 给出检查项：产品名称/图标/关于、onboarding、通知、菜单、安装器/卸载项、任务栏、CLI/help、deep link、数据目录、单实例锁、daemon/socket、凭据命名空间、错误报告、更新源、下载名与网站支持链接等。

正式标识/图标使用原创或已授权 Porpita 资产，覆盖 ico/icns/png/托盘等实际包装尺寸。不以空白图标、Orca 图标或只改窗口标题通过验收。不要求先做品牌设计研究；完成一个简洁一致的可交付图标即可。

## 不得盲目全文替换

下列可以保留 Orca 名称，但必须在清单中说明：上游版权和 MIT、第三方作者、源代码 provenance、内部 DTO 的 `authority: 'orca'` / `inputOwner: 'orca'`、现有 SDK 类型名、兼容插件 global、历史记录格式和被外部 Harness 识别的协议。

这些字段是兼容标识，不是用户所见品牌。首次产品化不应为了“零字符串”造成整个 wire/schema 迁移。新增代码的公开名称用 Porpita；兼容别名只在已说明范围保留。

## 数据与外部出口

Porpita 默认使用独立 userData、缓存、日志、证书/凭据命名空间和协议，不覆盖原 Orca。旧数据导入是显式功能，不自动在原目录读写。

更新、遥测、崩溃报告、支持链接、登录回调、模型代理、registry/CDN、远端安装脚本都逐项登记真实归属。原 Orca 专属收集/发布/账户服务不应继续被默认调用。能用公开上游资源的，注明来源且遵守使用条件；需要自有后台但未提供时关闭或改为用户可配置，不能指向虚构域名。

普通模型供应商、GitHub/GitLab、用户 SSH/自有远端是正常第三方功能，不因名称扫描而删除。初代可采用手动更新安装包；自动更新必须指向真实 Porpita 源才启用，不能接受 Orca 包覆盖 Porpita。

## 许可与署名

核查基线的 Orca `LICENSE` 为 MIT，版权为 Lovecast Inc.；ACS 为 Sustainable Use License 1.0。保留各自适用声明和依赖许可，不把整个组合产品简单改成 MIT，也不因用户拥有仓库就推定所有贡献均可重新许可。公开商业发布/重新许可需另行确认权利；本轮可以完成内部候选应用和授权范围内的交付。

“清理 Orca 残留”不包括删除法定声明、伪装原创来源或使用上游签名/发布账户。关于页可以有“基于 Orca 开源项目”的第三方致谢，产品标题仍为 Porpita。

## 品牌故事

用户确认的产品愿景：让分布式智能个体通过协作形成统一的系统级智能。2025 年论文《Zooid arrangement and colony growth in Porpita porpita》（DOI 10.1186/s12983-025-00565-3）把该动物描述为高度整合的群体；这是命名隐喻，不是声称产品已有生物学意义上的智能或已获得相关名称/商标权。该介绍可放关于/文档，不要求新增首页内容。

## 验收

安装、桌面入口、窗口、通知、CLI、关于、卸载与重开均呈现 Porpita；与原 Orca 可并存；检查实际可达外部服务配置，无旧更新/遥测误连。许可证/内部兼容字符串允许存在，不以全仓 grep 零结果为目标。
