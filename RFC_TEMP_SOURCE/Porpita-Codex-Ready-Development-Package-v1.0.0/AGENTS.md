# Porpita 实施约束

当前用户明确要求 > 本包规范 > 现有仓库与上游工程规范 > 历史开发包/审计建议。

本包覆盖旧的“先做插件才考虑 Fork”和“Root/Route 显式构成主导航”设想；不覆盖 ACS 已采用的稳定消息语义。旧审计里提出的防御扩展或全矩阵资格不是本轮新主线。

实现优先：原生复用、薄适配、实际通信、完整应用、品牌独立、最小必要测试。不重建 UI 设计系统，不增加只为防御而存在的平行账本。继承仓库 AGENTS 指令时，同样要检查其是否依赖 Orca 专属发布服务，并进行 Porpita 范围内的适配。

本包中的新增类型、方法名、工作树布局标为“建议目标”，不假冒上游已有 API。已有等效代码直接复用。

参考源的默认分支会变化。使用 source-lock 中固定提交理解依据，采用当前工作树时记录差异，不随时追踪上游造成移动目标。不得让包检查测试代替产品验收。
